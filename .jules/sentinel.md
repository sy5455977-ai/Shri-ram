## 2025-05-14 - PII Leakage in Centralized Firestore Error Handler
**Vulnerability:** The centralized `handleFirestoreError` function was logging and throwing raw PII, including the user's UID, email address, and full Firestore document paths containing internal IDs.
**Learning:** Centralized error handlers often aggregate all context (auth state, paths) without sanitization. Additionally, throwing stringified JSON in Error objects is a major anti-pattern that can cause secondary crashes and complicates UI error handling. Path sanitization using simple index-based logic is brittle if leading slashes are not accounted for.
**Prevention:** Implement a sanitization layer that handles path normalization (sourcing leading slashes) and redacts PII (UIDs, emails) from BOTH logs and user-facing errors. Always throw standard string-based Error messages to ensure system stability and predictable UI behavior. Use generic messages for users while providing sanitized context for developers in the console.
